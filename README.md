# ربات معاملاتی BTCUSDT — کوینکس فیوچرز (v5)

پیاده‌سازی نهایی استراتژی «شکست فشرده + سیگنال مستقل Whale + تریلینگ پلکانی» که در طول این تحقیق ساخته و روی ۶ سال داده تاریخی (۲۰۲۰-۲۰۲۶) اعتبارسنجی شد (PF کلی≈۱.۷۹، بازده Out-of-Sample مثبت روی ۲۰۲۴-۲۰۲۶).

## معماری

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────┐
│  کوینکس API │ <── │   bot.py (حلقهٔ   │ ──> │  data/*.jsonl│
│  (عمومی+خصوصی)│     │   اصلی، هر ساعت) │     │ (لاگ/وضعیت) │
└─────────────┘     └──────────────────┘     └──────┬──────┘
                            │                         │
                     engine/strategy.py         dashboard/server.py
                     engine/risk_manager.py      (FastAPI, پورت 8000)
                     engine/broker.py
```

بات و داشبورد دو process/container جدا هستند و فقط از طریق فایل‌های `data/` (که در یک Docker volume مشترک است) ارتباط دارند — یعنی اگر داشبورد کرش کند، بات مستقل به کار خودش ادامه می‌دهد.

## چرا Docker روی VPS، نه GitHub Codespaces

Codespaces محیط توسعه است: با idle-timeout متوقف می‌شود و سقف ساعت رایگان ماهانه دارد. برای معاملهٔ واقعی که باید واقعاً ۲۴/۷ بدون وقفه کار کند (حتی وسط یک پوزیشن باز)، یک VPS ارزان با `restart: unless-stopped` در Docker Compose قابل‌اعتمادتر است — اگر پردازش کرش کند، خودش دوباره بالا می‌آید؛ اگر سرور ری‌استارت شود، به‌خاطر Volume ماندگار، وضعیت (تعداد معاملات کاغذی، PnL روزانه) از دست نمی‌رود.

## نصب سریع (روی هر VPS با Docker)

```bash
git clone <این-ریپو> coinex-bot && cd coinex-bot
cp .env.example .env
nano .env   # مقادیر را پر کنید (برای شروع کاغذی، کلید API لازم نیست)
docker compose up -d --build
```

داشبورد در `http://<IP-سرور>:8000` در دسترس است.

## چرخهٔ کاغذی → زنده (طراحی عمداً محافظه‌کارانه)

**این بخش را حتماً بخوانید.** برخلاف درخواست اولیه («بعد از یک هفته خودکار وارد حالت واقعی شود»)، به‌جای زمان‌محور، به‌صورت **آستانه‌محور + تأیید دستی اجباری** طراحی شد، چون یک هفته (احتمالاً کمتر از ۲۰-۳۰ معامله) اعتبار آماری کافی نمی‌دهد. برای رفتن به حالت زنده هر دوی این‌ها لازم است:

1. حداقل ۵۰ معاملهٔ کاغذی کامل شده باشد (قابل تغییر با `MIN_PAPER_TRADES` در `.env`)
2. شما دستی فایل `data/CONFIRM_LIVE.txt` را با محتوای دقیق `I_UNDERSTAND_THE_RISK` بسازید:
   ```bash
   echo -n "I_UNDERSTAND_THE_RISK" > data/CONFIRM_LIVE.txt
   ```
   بدون این فایل، ربات **هرگز** به حالت زنده نمی‌رود، حتی اگر شرط اول برقرار باشد.

بعد از رفتن به حالت زنده، برای برگشت به کاغذی کافی است همان فایل را حذف کنید.

## محافظت‌های ایمنی داخلی

- **Circuit Breaker روزانه**: اگر ضرر تجمعی امروز از `MAX_DAILY_LOSS_PCT` (پیش‌فرض ۳٪) بگذرد، تا فردا هیچ معاملهٔ جدیدی (نه کاغذی نه زنده) باز نمی‌شود.
- **ریسک ثابت هر معامله**: `RISK_PER_TRADE_PCT` (پیش‌فرض ۱٪) — دقیقاً همان مدیریت سرمایه‌ای که در بک‌تست نهایی استفاده شد.
- **حداکثر یک پوزیشن هم‌زمان.**
- کلیدهای API فقط از `.env` خوانده می‌شوند، هرگز در کد نیستند؛ `.env` در `.gitignore` است.

## محدودیت‌های صادقانه که باید بدانید

- **دادهٔ Order Flow واقعی در Kline عمومی فیوچرز کوینکس موجود نیست.** بک‌تست ما از `TakerBuyBase` واقعی صرافی (که فقط در دادهٔ تاریخی دانلودی موجود بود) برای سیگنال Whale استفاده کرد. در نسخهٔ زنده، چون این فید عمومی در دسترس نیست، فعلاً با یک پروکسی محافظه‌کارانه (نصف حجم) جایگزین شده — یعنی سیگنال Whale در حالت زنده دقیقاً همان چیزی نیست که بک‌تست شد. اگر به یک فید Order Flow واقعی (مثلاً از یک ارائه‌دهندهٔ دیگر) دسترسی دارید، `klines_to_df()` در `bot.py` باید با آن جایگزین شود.
- **این هنوز یک بک‌تست تاریخی است.** حتی با تمام دقتی که در Walk-Forward validation به‌کار رفت، بازار زنده اسپردها، اسلیپیج واقعی، و رفتارهای جدید متفاوتی خواهد داشت که هیچ بک‌تستی نمی‌تواند کامل شبیه‌سازی کند.
- **اهرم (Leverage) پیش‌فرض ۲x است** (`LiveBroker.__init__`) — این عدد در هیچ‌جای بک‌تست ما اعتبارسنجی نشده (بک‌تست فرض می‌کرد بدون اهرم/۱x معامله می‌شود)؛ اگر آن را بالا ببرید، افت سرمایهٔ -۹.۵٪ که در بک‌تست دیدیم متناسب با اهرم بزرگ‌تر می‌شود.
- کد CoinEx client بر اساس مستندات رسمی فعلی نوشته شده ولی **هرگز با کلید واقعی تست نشده** (من به حساب شما دسترسی ندارم). حتماً اول با مبلغ خیلی کوچک تست کنید.

## فایل‌ها

| فایل | نقش |
|---|---|
| `engine/coinex_client.py` | کلاینت REST کوینکس v2 (امضای HMAC-SHA256 طبق مستندات رسمی) |
| `engine/strategy.py` | همان منطق اعتبارسنجی‌شدهٔ v5، نسخهٔ Bar-by-bar برای اجرای زنده |
| `engine/broker.py` | انتزاع بروکر: `PaperBroker` / `LiveBroker` |
| `engine/risk_manager.py` | دروازهٔ ایمنی کاغذی→زنده + Circuit Breaker |
| `bot.py` | حلقهٔ اصلی |
| `dashboard/server.py` | داشبورد وب (FastAPI) |
| `docker-compose.yml` | اجرای هم‌زمان بات + داشبورد با Volume مشترک |
